# Polaris — бронирование лаундж-зон

Полноценное Rails-приложение для управления лаундж-зонами частного здания:
каталог зон, бронирование с модерацией, личный кабинет члена клуба и админка
с аналитикой. Интерфейс — на русском языке.

## Стек

| Слой | Технология |
| --- | --- |
| Фреймворк | Ruby on Rails 8.1, Ruby 3.2 |
| БД | PostgreSQL 14 (exclusion constraint против двойных броней) |
| Фронтенд | Hotwire (Turbo + Stimulus), Importmap, Tailwind CSS 4 |
| Аутентификация | встроенный генератор Rails 8 (has_secure_password) + роли |
| Авторизация | Pundit (роли: член клуба / менеджер / администратор) |
| Фоновые задачи | Solid Queue (БД-backed), письмо-напоминания по расписанию |
| Аналитика | Chartkick + groupdate |
| Тесты | RSpec + FactoryBot + shoulda-matchers |
| Отчёты | caxlsx (Excel) |
| Качество | RuboCop (rails-omakase), Brakeman, bundler-audit |

## Возможности

- **Каталог комнат** — публичная витрина: тип (кино/караоке/бильярд/лаундж/PS),
  номер по зданию, вместимость, удобства, базовая ставка, минимальная/максимальная длительность.
- **Тарифная сетка** — цена «будни/выходные × день/вечер/ночь» по каждой комнате
  (`PriceRule`): каждая минута брони тарифицируется по действующему окну,
  вне окон — базовая ставка. Окна могут пересекать полночь.
- **Бронирование** — с модерацией или автоподтверждением (флаг комнаты);
  цена фиксируется на момент создания; флаг «детское мероприятие» увеличивает буфер уборки до 30 минут.
- **Буферы уборки** — после брони комната занята ещё `cleaning buffer` минут;
  буфер учитывается и в валидациях, и в exclusion-констрейнте PostgreSQL
  `reservations_no_overlaps` (btree_gist + tsrange + make_interval) — двойное
  бронирование и наезд на уборку исключены даже при гонке запросов.
- **Правило караоке** — две караоке-брони не ставятся в смежные комнаты
  одновременно (граф смежности `zone_adjacencies`).
- **Шахматка** (`/admin/schedule`) — сетка «комнаты × часы» со статусами
  «свободно / занято (подтверждена, на рассмотрении) / уборка», навигация по дням.
- **Таймеры** — на дашборде карточки активных броней с обратным отсчётом
  (Stimulus): предупреждение за 10 минут до конца, красный статус при просрочке.
- **Продление на месте** — кнопка «+30 мин» у активной брони с проверкой
  конфликтов и доплатой по действующим тарифам.
- **Отчёт «занятые часы по комнатам»** (`/admin/reports/room_hours`) —
  фильтр по датам и выгрузка в Excel (caxlsx).
- **Личный кабинет** — предстоящие и прошедшие брони, отмена.
- **Аналитика** — брони по дням, выручка по неделям, пиковые часы, дни недели,
  статусы, популярные зоны, загрузка зон в % (Chartkick).
- **Уведомления** — письма при создании/подтверждении/отклонении брони и
  напоминание за сутки (recurring-задача Solid Queue).
- **Регистрация** — открытая для членов клуба (роль member).

## Запуск

Требуются: Ruby 3.2+, PostgreSQL, Redis не нужен.

```bash
bin/setup            # гемы, БД, сиды
bin/dev              # сервер + Tailwind + Solid Queue
```

Открыть http://localhost:3000

Демо-доступ после сидов:

| Роль | Логин | Пароль |
| --- | --- | --- |
| Администратор | admin@polaris.test | password123 |
| Менеджер | manager@polaris.test | password123 |
| Член клуба | anna@polaris.test | password123 |

В dev-окружении письма открываются в браузере (letter_opener).

## Онлайн-оплата (bePaid)

Предоплата брони картой через Checkout API bePaid (интеграция по образцу varka):
после создания брони гость сразу уходит на страницу оплаты bePaid; итог приходит
webhook'ом, статус брони и письмо «оплачено» обновляются автоматически.
Админ может зафиксировать оплату «на месте» (наличные/карта на ресепшене).

Ключи магазина (ENV или `bin/rails credentials:edit` → `bepaid:`):

```bash
BEPAID_SHOP_ID=...      # Магазины → Подробнее → Ключи магазина
BEPAID_SECRET_KEY=...
BEPAID_PUBLIC_KEY=...   # для проверки подписи webhook (в production обязателен)
BEPAID_TEST_MODE=true   # по умолчанию: включён везде, кроме production
```

Тестовый платёж: **4111 1111 1111 1111**, любой будущий срок, любой CVC/CVV.

Локальная проверка webhook (без подписи работает вне production;
все поля — внутри `transaction`, как присылает bePaid):

```bash
curl -u $BEPAID_SHOP_ID:$BEPAID_SECRET_KEY -X POST http://localhost:3000/bepaid/webhook \
  -H 'Content-Type: application/json' \
  -d '{"transaction":{"status":"successful","amount":10000,"currency":"BYN","test":true,
       "tracking_id":"<tracking_id платежа>","uid":"test-uid"}}'
```

## Структура

- `app/models/reservation.rb` — домен брони: валидации, снапшот цены и буфера,
  конечный автомат статусов (`TRANSITIONS`), `extend!` (продление).
- `app/models/reservations/price_calculator.rb` — поминутный расчёт по тарифной сетке.
- `app/models/price_rule.rb` — тарифные окна (будни/выходные, переход через полночь).
- `app/models/schedule/grid.rb` — шахматка занятости.
- `app/models/reports/` — отчёт «занятые часы» и его Excel-экспорт.
- `app/models/analytics/dashboard.rb` — запросы для дашборда.
- `app/policies/` — Pundit-политики.
- `db/migrate/…_add_booking_attributes_to_reservations.rb` — exclusion constraint
  `reservations_no_overlaps` с учётом буфера уборки.
- `config/recurring.yml` — ежедневные напоминания (10:00, production).
